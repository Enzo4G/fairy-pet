# 更新记录

按时间倒序。每条对应一次对外发布；二进制在 [Releases](../../releases)。

## v2.0.4 · 2026-11-08 · 窗口叫得回来，小窗不再空白

- **修**：v2.0.3 “把所有候选窗口都抬起来”是错的——Hana 会挂一个永远不加载的空 Chromium 窗口（标题是 agent 名，纯白，关不掉）。现在只抬一个：优先抬「用户最后一次真正聚焦过的那个窗口」（每 900ms 记一次），没有记录才按「可见 > 标题等于产品名 > 面积」排。
- **修**：进程还活着但窗口叫不起来时，不再启动第二份——那正是空窗口的来源。改为气泡提示“再点一次”。
- **修**：托盘隐藏的客户端被 `ShowWindow` 抬起来后不能操作——窗口能画，但 Electron 仍以为自己是隐藏的，点击全吞。单例交接才是应用自己的恢复路径：再启动一次 exe，运行中的那份执行 `win.show()` + `moveTop()` + `focus()`，第二个进程拿到锁失败后自行退出（实测退出码 0，不多开窗口）。只有「已可见」或「已最小化」的窗口才从外部抬。
- **修**：小窗打开时不立即显示对话。`open_chat` 先把消息清空，而生成中的回合又禁止读历史（避开 Hana 改写会话文件），于是只剩占位文字。现在保留已渲染的内容，回合结束后重试读取（最多 8 次），仅在完全没内容时才提示「正在生成，结束后自动刷新」。
- **修**：Hana 里切了会话而小窗还缓存着旧会话时，`sessions` 回报的 current 与已显示的不一致就立即补读一次。
- **修**：冷启动时点「打开客户端」只报启动失败。日志里是 `WinError 740`——HanaAgent 在兼容性设置里被勾了「以管理员身份运行」（`AppCompatFlags\Layers`），普通 `CreateProcess` 起不来。改为走 shell 启动（等同双击），UAC 允许后正常拉起。
- **新**：宠物右键菜单加「指定 Hana 程序…」/「指定 dsh 程序…」，自动识别不到时可以手动选一次并记住；自动识别也会过滤安装器里的卸载器（`Uninstall HanaAgent.exe`）。
- **新**：托盘右键菜单加「回到默认位置」——改了分辨率或显示缩放后宠物跑掉了，点一下回右下角；宠物完全不在任何屏幕内时会自动回位。
- **修**：补回 `_user_hidden` 初始化（上一版误删，`watch_foreground` 在某些置顶模式下会抛 AttributeError）。

## v2.0.3 · 2026-11-08 · 面板失灵三连修

- **修**：Hana 版「关于」点了没反应——`hashlib` 没 import，窗口构造时就 `NameError`，而窗口版没有控制台，异常直接消失。现在失败写进日志并在气泡上提示。
- **修**：「打开客户端」只叫醒一个窗口。客户端往往不止一个顶层窗口（HanaAgent 同时有 `HanaAgent` 和每个 agent 一个窗），以前只抬一个，被抬的那个可能恰好不是你看的那个。现在候选全部抬起，最大的最后抬以占据前台。
- **修**：窗口只看得见但已最小化时误报成功（`IsWindowVisible` 对最小化窗口仍为真），导致“点了没反应”也不报错。现在同时要求非最小化。
- **修**：右键菜单每次重建都带 `self` 当父，菜单永远不销毁——按多就攒多，越攒越卡。改成无父 + `WA_DeleteOnClose` + `deleteLater()`。
- **改**：菜单打开期间暂停后台轮询（鼠标跟随、指标、用量、前台检测、屏幕校正、贴边检测），事件循环不再和它们抢主线程。
- **改**：窗口枚举不再收输入法子窗、拖盘辅助窗（`GetParent` 非空 / `WS_EX_TOOLWINDOW`）；抬窗加了重试与 `SwitchToThisWindow` 兜底，日志里能看到「可见/前台」。

## v2.0.2 · 2026-11-07 · 客户端藏进托盘也能叫回来

- **修**：「打开客户端」以前只认“可见”的窗口，而托盘隐藏的客户端窗口不可见，于是永远报“没找到窗口”。现在枚举不过滤可见性，按“可见 + 面积”挑主窗口；最小化走 `SW_RESTORE`，被隐藏走 `SW_SHOW`，系统拒绝抢焦点时用 `AttachThreadInput` 绕过去。
- **新**：客户端没开时会自己启动——配置 `clientExe` → 运行中进程 → 安装器卸载记录 → 常见安装目录，都没有才弹窗让用户选一次。
- **新**：`FairyPet\fairy.log` 运行日志（启动、端口选择、客户端启动、任务失败、未捕获异常，512KB 轮换）。

## v2.0.1 · 2026-11-06 · 贴边隐藏 / 掉不出屏幕 / 权限可切

一句话：贴边能藏起来了，改分辨率不会再把它甩丢，dsh 版的权限也能在小窗里直接切。

### 新功能

**贴边隐藏**（右键菜单勾选，默认关）

拖到屏幕任意一条边松手，身体就滑出去，只留本体 1/10——露出来的是眼球边缘那一角，不是透明光环的留白。鼠标停上去探出 1/3，按住可以直接把它拖出来；只有原地松手（没拖动过）才带平移动画滑回原位。判定贴不贴边看的是**鼠标**离边缘多远，不是宠物离边缘多远，所以大字号、拖过头都照样生效。

**不会被甩出屏幕**

每 1.5 秒自检一次位置。改分辨率、拔掉副屏、把宠物拖到屏幕外，只要不到 1/3 还落在可视区，就会被拉回来。启动时也会先校正上次存的位置。

**权限可在小窗里切**（dsh 版）

「权限」按钮现在是完整菜单：仅可查看 / 工作区内修改 / 完全权限，当前项打勾。走的是客户端同一入口（在会话里执行 `/permission <preset>`），改完标签立刻跟上。

「模式」（标准 / PTC / 精简 / Cordis）只能在对话第一条消息之前选——这是 dsh 的规则，已经开始的会话它自己也会拒绝。以前点了没反应，现在会在提示行写原因。

### 变化

**Hana 版去掉「新建对话」**

Hana 的会话列表由客户端维护，外部进程建出来的会话不会实时出现在侧栏，点一次就留一个看不见的空会话。要开新对话请在 Hana 里点，桌宠的下拉里选中它即可。

### 修复

- **认错端口**：以前按"首页里有没有 dsh 字样"挑端口，本机另一个服务刚好也写着 dsh，于是连过去、整窗报「dsh 拒绝授权」。现在先发一次 `session/list`，验证通过才认。
- **贴边后悬停没反应**：拖到边缘松手时指针本来就压在窗口里，`enterEvent` 永不来，改成 150ms 轮询指针位置。
- **弹回后重启又跑出去**：原来存的是拖动前那个越界坐标，现在存弹回后的落点。
- **「没后端就自杀」**：从未连上过时只空转等待，连过再断才退出——开机自启时桌宠可能比客户端先起来。
